# ROS 2 Services

## Introduction

ROS 2 services provide a request-response communication pattern that is essential for humanoid robotics applications. Unlike topics which provide asynchronous communication, services offer synchronous communication where a client sends a request and waits for a response from a server. This pattern is particularly useful for operations that require immediate results or for configuring robot parameters.

## Key Concepts

- **Service Server**: Provides a specific functionality and responds to requests
- **Service Client**: Sends requests to service servers and waits for responses
- **Service Interface**: Defines the request and response message types
- **Synchronous Communication**: Client waits for server response before proceeding

## Service Architecture

Services in ROS 2 follow a client-server model where:

1. A service server advertises a service with a specific name and interface
2. A service client connects to the service and sends requests
3. The server processes the request and sends back a response
4. The client receives the response and continues execution

This architecture is ideal for humanoid robotics operations like:
- Robot configuration and calibration
- Action execution confirmation
- Sensor data querying
- System status checks

## Service Client Implementation

<CodeExample
  title="Service Client"
  language="python"
  code={`import rclpy
from rclpy.node import Node
from example_interfaces.srv import AddTwoInts

class MinimalClient(Node):

    def __init__(self):
        super().__init__('minimal_client')
        self.cli = self.create_client(AddTwoInts, 'add_two_ints')
        while not self.cli.wait_for_service(timeout_sec=1.0):
            self.get_logger().info('Service not available, waiting again...')
        self.req = AddTwoInts.Request()

    def send_request(self, a, b):
        self.req.a = a
        self.req.b = b
        future = self.cli.call_async(self.req)
        rclpy.spin_until_future_complete(self, future)
        return future.result()

def main():
    rclpy.init()
    minimal_client = MinimalClient()
    response = minimal_client.send_request(1, 2)
    minimal_client.get_logger().info(
        'Result of add_two_ints: %d' % response.sum)
    minimal_client.destroy_node()
    rclpy.shutdown()

if __name__ == '__main__':
    main()`}
  description="This example shows how to create a service client that calls the service server."

## Practical Applications in Humanoid Robotics

Services are particularly useful in humanoid robotics for:

- **Motor Control**: Requesting specific joint positions or checking motor status
- **Sensor Queries**: Requesting current sensor readings or configuring sensor parameters
- **Behavior Control**: Activating specific robot behaviors or checking behavior status
- **System Configuration**: Changing robot parameters or getting system status

## Best Practices

1. **Timeout Handling**: Always implement proper timeout handling in service clients
2. **Error Handling**: Handle service failures gracefully in both clients and servers
3. **Service Naming**: Use descriptive and consistent service names following ROS 2 conventions
4. **Resource Management**: Properly clean up service handles to prevent resource leaks

## Summary

ROS 2 services provide a reliable request-response communication pattern essential for humanoid robotics applications. Understanding how to implement both service servers and clients is crucial for developing responsive and interactive humanoid robot systems.
